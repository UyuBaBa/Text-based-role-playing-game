# Как поднять игру на сервере

Цель: игра живёт в интернете сама по себе. Твой компьютер может быть выключен —
друзья открывают ссылку, вводят пароль и играют в любое время.

Всё, что нужно для этого, уже лежит в проекте: `Dockerfile`, `railway.json`,
`.dockerignore`. Дальше — только действия в твоём аккаунте, куда мне хода нет.

---

## Где размещать (проверено в сентябре 2026)

Игре нужны три вещи: Docker, постоянно работающий процесс и **диск для сохранений**.
Последнее и отсекает большинство бесплатных тарифов: без диска файлы живут до первого
перезапуска, а перезапуск случается сам собой.

| Хостинг | Цена | Всегда включён | Сейвы переживают перезапуск |
|---|---|---|---|
| **Oracle Cloud Always Free** | бесплатно, бессрочно | да | да, обычный диск |
| **Render** | бесплатно, 750 ч/мес | нет: спит через 15 мин, просыпается ~1 мин | **нет**, диск только на платном |
| **Google Cloud Run** | бесплатно, 2 млн запросов/мес | нет, засыпает до нуля | **нет**, файлы временные |
| **Railway** | ~5 $/мес | да | да, том на `/data` |
| Fly.io | — | — | бесплатного тарифа для новых больше нет |
| Koyeb | — | — | бесплатный тариф закрыт для новых |
| Hugging Face Spaces | — | — | Docker требует подписки PRO |

**Бесплатно и по-настоящему работает — Oracle Cloud Always Free.** Это не «платформа»,
а обычная виртуальная машина: 2 ядра ARM и 12 ГБ памяти навсегда, свой диск, ничего
не засыпает. Возни на полчаса больше, зато потом не трогаешь.

**Проще всего — Railway**, но это ~5 $/мес.

**Render подойдёт, чтобы попробовать.** Разворачивается за пять минут, но сохранения
будут пропадать при каждом пробуждении, а первый заход после простоя ждёт около минуты.

Отдельно от хостинга платится Gemini — по твоему ключу, за всех игроков сразу.

## Oracle Cloud Always Free — по шагам

Бесплатно и бессрочно. Карту при регистрации просят для подтверждения личности,
с ресурсов «Always Free» денег не списывают.

### 1. Завести машину

1. cloud.oracle.com → создать аккаунт, выбрать регион поближе.
2. **Compute → Instances → Create Instance**:
   - образ: **Ubuntu** (любой свежий LTS);
   - форма: **Ampere A1 (ARM)**, 1-2 ядра и 6-12 ГБ — это и есть бесплатный предел;
   - обязательно **скачать приватный SSH-ключ**, который предложат: второй раз его
     не покажут.

> Если пишет «Out of capacity» — обычное дело: бесплатные ARM-машины разбирают.
> Помогает сменить Availability Domain в том же окне, выбрать другой регион
> или повторить попытку через несколько часов.

3. **Networking → Virtual Cloud Network → Security Lists → Default Security List →
   Add Ingress Rule**:
   - Source CIDR: `0.0.0.0/0`
   - Destination Port Range: `80` (и `443`, если будет домен)

   Это облачный брандмауэр Oracle. Про брандмауэр внутри Ubuntu позаботится скрипт.

### 2. Положить игру на машину

Зайти по SSH (`ssh -i ключ.key ubuntu@АДРЕС`) и забрать проект — проще всего из
своего репозитория на GitHub:

```
sudo apt update && sudo apt install -y git
git clone https://github.com/ТВОЙ_ЛОГИН/НАЗВАНИЕ.git rpg
cd rpg
```

Без GitHub можно скопировать папку прямо с компьютера:

```
scp -i ключ.key -r "Game Test 1" ubuntu@АДРЕС:~/rpg
```

### 3. Запустить одной командой

```
sudo bash deploy/setup.sh
```

Скрипт спросит ключ Gemini и пароль для игроков, а дальше сам: поставит Docker,
откроет порт в брандмауэре Ubuntu, соберёт образ, запустит игру с автозапуском после
перезагрузки и напечатает готовую ссылку.

Сохранения живут в `/var/lib/rpg-data` — вне контейнера, поэтому переживают
и обновления, и перезагрузку машины.

### 4. По желанию: HTTPS вместо http

Без домена игра работает по обычному `http://АДРЕС`, и пароль летит открытым текстом.
Бесплатный домен берётся на duckdns.org за минуту; направь его на IP машины и запусти:

```
sudo GAME_DOMAIN=имя.duckdns.org bash deploy/setup.sh
```

Рядом поднимется Caddy, который сам получит сертификат Let's Encrypt и будет держать
его в актуальном виде. Ссылка станет `https://имя.duckdns.org`.

### Потом

| Что нужно | Команда |
|---|---|
| Обновить игру после правок | `git pull && sudo bash deploy/update.sh` |
| Посмотреть, что происходит | `docker logs -f rpg` |
| Перезапустить | `docker restart rpg` |
| Сменить пароль | `sudo GAME_CODE=новый bash deploy/setup.sh` |
| Забрать сохранения | они в `/var/lib/rpg-data` |

## Railway, шаг за шагом

### 1. Положить код на GitHub

Railway забирает проект из репозитория. В папке с игрой:

```
git init
git add .
git commit -m "Текстовая RPG на Gemini"
```

`.gitignore` уже настроен: `.env` с ключом, сейвы, логи и `tools/` в репозиторий
не попадут. **Проверь это перед отправкой** — ключ в публичном репозитории
придётся сразу отзывать:

```
git status --short
```

Создай пустой репозиторий на github.com (можно приватный) и отправь код:

```
git remote add origin https://github.com/ТВОЙ_ЛОГИН/НАЗВАНИЕ.git
git branch -M main
git push -u origin main
```

### 2. Создать проект в Railway

1. Зайти на railway.app через GitHub.
2. **New Project → Deploy from GitHub repo** → выбрать репозиторий.
3. Railway увидит `Dockerfile` и соберёт образ сам. Ничего настраивать не нужно.

### 3. Прописать переменные

Вкладка **Variables** у сервиса, кнопка **New Variable**:

| Переменная | Значение | Зачем |
|---|---|---|
| `GEMINI_API_KEY` | твой ключ | без него игра не сгенерирует ни строчки |
| `GAME_CODE` | пароль для друзей | **обязательно**: без него игра не запустится |
| `GEMINI_DEFAULT_MODEL` | `gemini-3.5-flash-lite` | необязательно |

`GAME_HOSTED=1` и `GAME_DATA_DIR=/data` уже заданы в `Dockerfile` — их вписывать
не надо.

> Пароль придумай нормальный, а не `1234`: адрес у сервиса угадываемый,
> а за каждый запрос платишь ты.

### 4. Подключить диск для сохранений

Без него файлы стираются при каждом обновлении игры, и все партии пропадут.

**Settings → Volumes → Add Volume**, точка монтирования: `/data`
Хватит и 1 ГБ — сейвы весят килобайты.

### 5. Открыть адрес наружу

**Settings → Networking → Generate Domain**. Появится ссылка вида
`название-production.up.railway.app`. Её и раздавай вместе с паролем.

## Что увидят игроки

1. Открывают ссылку → экран с одним полем.
2. Вводят пароль → попадают в главное меню.
3. Дальше всё как обычно: свой мир, свой персонаж, свои сохранения.

Пароль спрашивается один раз: браузер запоминает вход на месяц.
У каждого игрока **своя отдельная игра** — чужих партий никто не видит.

---

## Что стоит знать

**Ключ один на всех.** Сколько бы человек ни играло, запросы идут по твоему ключу
и в твою квоту. Пароль знают только приглашённые — на этом вся защита и держится.
Если ссылка с паролем уйдёт дальше, смени `GAME_CODE` в Variables: сервис
перезапустится, и все старые входы перестанут работать.

**Сколько это в запросах.** Один ход игрока — один запрос. Старт игры — один,
бой — два. Час игры это примерно 40-60 запросов на человека.

**Совместная игра.** Если захочется, чтобы все играли одну партию на всех,
добавь переменную `GAME_COOP=1`.

**Перезапуск сервиса** (обновление кода, смена переменных) обрывает текущие партии:
они живут в памяти. Сохранения на диске остаются — игроки нажмут «Загрузить»
и продолжат с последнего автосейва.

**Домашний запуск никуда не делся.** `python run.py` работает как раньше,
`--share` и `--internet` тоже.

## Если что-то пошло не так

**Сервис падает сразу после запуска.** Посмотри логи в Railway: скорее всего там
`Игра запущена на сервере без пароля` — не задан `GAME_CODE`.

**Игра открывается, но не генерирует мир.** Не задан или неверен `GEMINI_API_KEY`.
На экране будет понятная надпись, подробности — в логах.

**Сохранения пропадают после обновления.** Не подключён диск на `/data` (шаг 4).

**Хочу проверить то же самое дома.** Серверный режим включается локально:

```
set GAME_HOSTED=1
set GAME_CODE=МОЙПАРОЛЬ
python -m uvicorn game.server:app --host 0.0.0.0 --port 8000
```
