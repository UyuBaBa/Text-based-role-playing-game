# Хроника — текстовая RPG на Gemini

Интерактивная текстовая игра в духе AI Dungeon: игрок задаёт сеттинг и персонажа,
Gemini генерирует предысторию мира и ведёт повествование, игрок на каждом шаге пишет
действие или реплику, сюжет реагирует на действие и на текущее состояние мира.

**Игра целиком живёт в браузере.** Сервера нет: страница сама считает механику и сама
ходит в Gemini. Выкладывается на GitHub Pages и работает вечно, ничего не поддерживая.

```
docs/           сайт — это всё, что нужно выложить
  index.html
  style.css
  js/
    config.js     ← ЕДИНСТВЕННЫЙ файл, который правишь: ключ и модели
    ui.js         интерфейс и экраны
    api.js        обращения к Gemini
    turn.js       окно контекста, схемы ответов, ход
    worldgen.js   генерация завязки
    state.js      состояние игры
    rules.js      дельты, усталость, отдых, отказы
    npc.js        симпатия
    combat.js     бой
    saves.js      сохранения в браузере
    prompts.js    системные промпты
dev/            проверки (на сайт не выкладываются)
```

## Как выложить

### Ключ вводит сам игрок

Ничего секретного в репозиторий не кладётся: при первом заходе игра просит вставить
собственный ключ Gemini, и он остаётся в браузере игрока.

Так пришлось сделать, и вот почему. Спрятать общий ключ в статическом сайте негде —
он виден любому, кто открыл страницу. Раньше это лечилось привязкой ключа к домену,
но новые ключи Gemini (начинаются на `AQ.`) такого ограничения не поддерживают: они
привязаны к служебной учётной записи. Старые ключи `AIza`, которые умели ограничение,
Gemini перестал принимать в сентябре 2026. Вдобавок Google сам ищет утёкшие ключи
и быстро их отключает — зашитый в публичную страницу ключ прожил бы недолго и утянул
бы за собой всю игру.

Google на этот счёт пишет прямо: не зашивайте ключи в веб-приложения, а для защиты
клиентского кода поднимайте прокси. Прокси — это снова сервер, поэтому выбран честный
путь: у каждого свой ключ.

Получить его бесплатно можно на
[aistudio.google.com/apikey](https://aistudio.google.com/apikey) — это пара минут,
и игра объясняет порядок прямо на первом экране.

### Выложить на GitHub Pages

```
git add .
git commit -m "Игра в браузере"
git remote add origin https://github.com/ТВОЙ_ЛОГИН/НАЗВАНИЕ.git
git push -u origin main
```

Затем в репозитории: **Settings → Pages → Source: Deploy from a branch → main / docs**.

Через минуту игра будет по адресу `https://ТВОЙ_ЛОГИН.github.io/НАЗВАНИЕ/`.

### Проверить локально

Файлы можно открыть и без сайта, но модулям нужен http, поэтому не двойным кликом:

```
cd docs && python -m http.server 8000
```
и открыть `http://127.0.0.1:8000`.

## Что сколько стоит

| Действие игрока | Запросов к Gemini |
|---|---|
| Создать мир | 1 |
| Ход | 1 |
| Ход при полном истощении | 0 — отказ сочиняет код |
| Начало драки | +1 (лист врага и запас реплик) |
| Раунд боя | 0 |
| Конец боя | 1 (возвращение в повествование) |
| Сжатие хроники | 1 раз в несколько десятков ходов |

Всё остальное — состояние, бой, симпатия, сохранения — считается в браузере и ничего
не стоит.

## Ключевые решения

### Числа считает код, а не модель

LLM плохо держит арифметику и склонна к дрейфу («здоровье 100 → 87 → 95 без причины»).
Поэтому единственный источник правды — объект состояния в браузере. Модель не помнит
здоровья и симпатии: они подставляются в промпт каждый ход, а в ответ она возвращает
не новые значения, а **дельты-предложения**, которые код зажимает в границы.

### Один ход = один запрос

Через `responseSchema` один вызов возвращает сразу всё: текст сцены, дельты состояния,
изменения инвентаря, участников сцены, заявку на драку и запись в хронику.

### Память без раздувания контекста

```
правила ведущего + карточка мира + хроника + состояние
+ персонажи рядом + ограничения по состоянию
+ последние 6 ходов дословно + действие игрока
```

Хроника пополняется полем `memory_update` того же запроса. Когда она переваливает за
6000 знаков, один отдельный запрос ужимает старую часть.

### Усталость и раны как приказ ведущему

Просить модель «учитывать усталость» бесполезно — согласится и забудет. Код смотрит на
пороги и вписывает в промпт прямое указание: при усталости выше 85 любая активная
попытка обязана провалиться. А при 90 и выше код отказывает сам, вообще не тратя запрос.

### Симпатия — число со шкалой поведения

От −100 до +100 на каждого значимого NPC. Код переводит число в ярлык и в инструкцию:

| Диапазон | Ярлык | Что требуется от модели |
|---|---|---|
| +60…+100 | Предан | помогает, делится, рискует ради игрока |
| +20…+59 | Дружелюбен | охотно общается, мелкие услуги |
| −19…+19 | Нейтрален | торг, безразличие |
| −59…−20 | Неприязнь | грубит, обманывает, завышает цену |
| −100…−60 | Враждебен | активно вредит, может напасть первым |

Шаг за ход ограничен ±25 — доверие не покупается репликой. Исключение — первая встреча:
персонаж может появиться уже врагом.

Давние знакомые выпадают из промпта (12 ходов без встречи), но остаются в журнале.

### Бой считает код, модель только озвучивает

`урон = атака + 2d6 − защита`. Две кости, а не одна: с одной исход читался по листу
противника ещё до первого удара — получалась ступенька из 100 % и 0 % побед без ничего
между ними. Подобрано замерами по 600-800 боёв на вариант:

| Противник | Побед | Длина боя |
|---|---|---|
| Задира 40/5/1 | 100 % | 2.8 раунда |
| Вооружённый 75/9/3 | 100 % | 5.1 раунда |
| Боец 95/12/4 | ~50 % | 6.3 раунда |
| Чудовище 130/16/7 | 0 % | — |

Усталость решает: против одного и того же врага 100 % побед у бодрого и 71 % при
усталости 95. Бегство — рабочий выход: 65-72 % успеха даже против чудовища.

Реплики врага генерируются пачкой на старте боя (уверен / ранен / при смерти /
побеждает) и дальше выбираются кодом по его состоянию — раунды не стоят запросов.

## Сохранения

Лежат в `localStorage` браузера: шесть слотов, автосейв после каждого хода и каждого
раунда боя. **После смертельного хода автосейв не пишется** — иначе «продолжить»
возвращало бы игрока ровно в момент гибели; так в слоте остаётся состояние на начало
рокового хода.

Куки не подошли: в них влезает 4 КБ, а партия с хроникой весит десятки килобайт.

Чистка истории браузера сотрёт сохранения, поэтому у каждого слота есть кнопка
«В файл» и обратная загрузка.

## Проверки

```
node dev/selftest.js    механика: клампы, отдых, пороги, симпатия, баланс боя
node dev/flowtest.js    весь путь игры с подставными ответами модели
```

`flowtest` подменяет `fetch` и прогоняет цепочку целиком: генерация мира → ход →
сборка контекста → отказ по усталости → драка → раунды → возвращение в повествование →
сохранения → обработка ошибок сети. Настоящий Gemini при этом не дёргается.

Для запуска нужен Node. Самой игре он не нужен — она работает в браузере.

## Что стоит знать

**У каждого своя квота.** Игроки не делят один лимит и не мешают друг другу: сколько
кто наиграл, столько сам и потратил. Обратная сторона — другу придётся потратить пару
минут на получение ключа.

**Ключ можно сменить.** Кнопка «Сменить ключ» в меню. Новый проверяется до сохранения,
и если он нерабочий, прежний остаётся на месте.

**Общий ключ всё-таки можно вписать** в `apiKey` в `config.js` — но только если сайт
не публичный (например, лежит у тебя на машине). Для GitHub Pages это значит подарить
ключ первому встречному.

**Гео-блокировка Google.** Gemini обслуживает не все страны. При запросе из
неподдерживаемой возвращается `400 User location is not supported` — игра распознаёт
это отдельно и советует включить VPN. Ключ тут ни при чём.

**Фильтры Gemini.** `BLOCK_NONE` выставлен по всем настраиваемым категориям, но часть
фильтров отключить нельзя. Если модель всё же откажется продолжать, игра предложит
переформулировать действие, а не упадёт.

**Модель иногда расходится с состоянием.** Опишет утрату предмета и забудет убрать его
из инвентаря. В промпте есть прямое требование, но полностью это не лечится — сверяй
инвентарь в журнале.

## Что можно доделать

- совместной игры нет: она требовала сервера и убрана вместе с ним;
- бой всегда один на один, групповых стычек нет;
- «Защита» в бою — способ пережить тяжёлый удар, а не выигрышная стратегия:
  в короткой схватке нападение выгоднее, и это видно по замерам;
- сохранения привязаны к браузеру: на другом устройстве их не будет, если не перенести
  файлом.

## История

Игра начиналась как локальный сервер на Python с FastAPI: он держал ключ, считал
механику и раздавал страницу. Умел совместную игру, раздачу по локальной сети и туннель
наружу через cloudflared. Всё это отпало вместе с сервером: статическому сайту нечего
раздавать, а игроки и так заходят по одной ссылке.

Та версия целиком лежит в истории git — коммит «Рабочая версия с сервером на Python
перед переносом в браузер». Вернуть файлы можно так:

```
git log --oneline
git checkout <хеш> -- game run.py requirements.txt Dockerfile deploy
```
